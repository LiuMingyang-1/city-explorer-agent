# 小红书活动采集：后处理实施与离线验收

更新：2026-11-12。当前社交来源仅小红书；网页发现、主办方补查和文本提取使用 DeepSeek；位置确认使用高德。此前六平台调研、登录及样本报告为历史记录，其余平台已从运行入口禁用。

本轮按用户要求实现后处理并离线测试。没有新增平台采集、真实模型调用、高德请求、正式库写入或系统定时任务。所有写库测试在独立临时目录运行并清理；缓存小红书只做输入检查，不把测试样本当作真实活动发布。

## 1. 配置：两套 API

| 本地配置 | 用途 | 说明 |
| --- | --- | --- |
| DEEPSEEK_API_KEY | 网页搜索、主办方补查、文本结构化 | 搜索与 deepseek-flash 共用 Key |
| EXPLORER_COLLECTION_MODEL | 文本提取模型名 | 默认 deepseek-flash；不是第三个 Key |
| AMAP_WEB_KEY | 高德 Web 服务 POI 与地理编码 | 服务端 Key；不是浏览器 JS SDK Key |

本地 `.env` 已追加空的 AMAP_WEB_KEY，原有值保留，文件继续被 Git 忽略。后处理实跑在读取这两个 Key 后才调用服务；缺高德配置时先失败，不消耗模型预算。小红书依赖本地独立浏览器登录态，不需要新增付费平台搜索服务。

## 2. 数据怎样走到 events

```text
小红书 JSONL → 规范化缓存（来源、发布时间、抓取时间、正文 hash）
  → 校验缓存：仅 xhs、正文 hash 一致、公开 canonical URL
  → 结构化直提 / deepseek-flash 理解（缺事实填 null，不输出坐标）
  → 字段证据、值与证据绑定、日期/价格/时长、有效性检查
  → 普通帖子需要主办方/政府/已识别发布者原站佐证
  → DeepSeek 搜索原站 → 直接获取允许的公开原文 → 重新提取并比对
  → 高德匹配唯一场馆/详细地址 → 坐标转换 → 场馆缓存
  → 生成原有 18 列 + provenance + 时效元数据 + 身份登记
  → 发布前重新验证原始证据和坐标绑定
  → SQLite 批次副本 upsert → 完整性检查 → 原子切换 CURRENT
```

只有城市、有效期或正文完整性不足的线索，可在没有编造、取消、过期等错误时补查一次主来源；补查后仍缺少事实、不满足硬性要求、无法佐证或坐标不唯一，进入拒绝报告，不写 events。不建立人工核验队列。来源暂时无法访问和活动取消分别处理。

### 2.1 本地能做什么，模型负责什么

- 本地：平台 ID/链接、正文及图片链接映射、时间单位转换、hash、重复内容识别、默认 NULL、固定枚举、JSON Schema、证据是否真实出现在文本中、值是否与证据对应、日期合法性、窗口及费用关系、身份登记、地理匹配、批次写入。
- 模型：非结构化长文本理解、多个活动的拆分及字段归属、主类别、回顾/预告/取消语义。模型输出最多三个活动，不允许调用数据库或生成来源可信等级。
- 已有结构化输入可以绕过模型，但必须通过同一套事实与证据校验。当前提供结构化适配入口，没有声称已具备通用网页 JSON-LD 自动解析器。
- 为提高准确性，description 当前使用逐字原文摘录；不生成无法逐项核实的宣传摘要。非空事实必须有短证据，不能只靠模型 confidence。
- 图片 OCR、视觉理解和视频转写未接入。只有海报、标题或视频而正文不足的记录，当前拒绝或通过独立原站补查；不会给 deepseek-flash 假定视觉能力。

三个时间字段仍 DEFAULT NULL；日常开放规则未验证前不展开成每天开放，更不把整个展期当连续开放。展期日期独立存 confirmed_start_date/confirmed_end_date 元数据。没有完整小时边界的记录可用于发现，不能自动排日程。

### 2.2 模型输出不是事实证明

解析失败最多重试一次；事实失败不通过再次生成“补齐”。额外字段、模型自报坐标/发布许可、凭空标题/价格/时长、无年份推测、无效日期、回顾、取消及未解决冲突均拒绝。

来源可信度由采集策略赋予，不读取模型的判断。小红书缓存强制从 unverified 开始，即使缓存中出现 authority=publisher 也不会获得信任。未取得主来源前，不消耗高德请求。

当前原站策略默认识别 HTTPS `.gov.cn` 及陕西历史博物馆已识别域名，额外主办方域名只能从受控配置加入。未知网站不会因为出现在搜索结果里就变成官方。此策略偏保守，可能漏掉有价值的活动，但不会把全部社交帖子当作主办方。

补查每活动一轮，最多尝试两个允许的原站；搜索摘要不作为主证据。直接获取原站正文后再次提取，名称、场馆和已知时间/地址有冲突或多个匹配时舍弃。原站动态渲染、访问限制、无法识别编码、正文过长等情况均可能导致拒绝；不绕过登录或验证。

HTTP 获取限制允许的域名和 HTTPS，检查并固定公开 IPv4 地址，每次重定向重新检查，限制响应类型、体积、超时和跳转次数；不携带平台 Cookie，也不请求私有地址。HTML 清洗为保守的文本处理，不能保证所有网站版式都已兼容。原站真实页面兼容性仍需后续实测。

## 3. 坐标确认

高德先搜索 POI，严格核对城市/行政代码、场馆全名或分馆、地址及门牌；不能直接拿第一条。多个匹配、返回分页不完整、地址冲突、错误城市都拒绝。POI 没有结果时，才对已有完整门牌地址做地理编码；只接受门牌号、单元号、门址，不接受道路或区县中心。

保留原始 GCJ-02 和转换版本，最终使用统一 WGS-84。选择入口时检查其与 POI 点的位置关系；要求入口而来源没提供时拒绝。缓存键包含名称、地址及入口要求，初值有效期 30 天；地址变化不复用旧条目。API 请求、响应体积及耗时有上限，错误不返回含 Key 的请求 URL。

转换代码参考 eviltransform，保留完整 BSD 许可。公开参考向量与该项目当前常量存在约 1e-6 度差异，离线检查采用 1.5e-6 度数值容差；另做五个西安数值点的往返检查。这些不是五个真实场馆的实地/独立位置验收，也不构成实际 POI 精度保证。高德 Key 配置后仍需核对至少五个真实场馆、同名分馆及地图落点。

## 4. 身份、时效与发布

- 身份由本地登记：同一个未知时间场次补齐时间后沿用 ID，多个场次无法确定对应关系时拒绝猜测。登记随批次保存，跨批次调用必须传入上一批登记。
- 事实检查和坐标完成后，发布前使用私有 witness 再计算目标记录，防止中间阶段修改价格等字段后绕过证据检查。witness 不进入发布包。
- 旧库通过 SQLite 一致性备份复制，事务 upsert 保留历史记录。不使用 mock seed，不直接复制正在使用的 WAL 主文件。
- 数据库、provenance 和 manifest 写完后校验 hash，再切换 CURRENT；同机写入锁保证单一发布者。失败保留旧指针和可读库，未发布目录留作诊断，不自动覆盖或删除。
- 第一次发现、最近抓取与事实核验分开。同一主来源正文 hash 不变时不会刷新核验时间；过期旧行丢出本次更新，仍可发布其他合格新活动。
- 已取消/结束或核验超过 36 小时的记录退出推荐。未知结束依据最多保留首次发现后 7 天；这些阈值是初值，仍需真实样本校准。
- 明确取消通知有独立入口，核对可信来源、活动名、场馆、来源身份和证据。取消后保留原行供历史回查；重抓旧帖不能复活活动。
- 读取器使用同批次数据库与元数据，完整性失败时保留旧读取器；推荐有效性在 SQL 的 100 条限制之前过滤，避免前 100 条过期记录遮挡有效记录。

发布读取器 `createReleasedRepository` 为独立接口，默认应用仍读取原 data/events.db，没有擅自替换主 Agent/Web 的装配。历史失效状态可从 getStatus 读取；前端展示该状态尚未接入。正式服务接入和夜间来源水位、取消通知自动匹配属于后续集成，当前未安装定时任务。

## 5. 运行入口

只检查缓存，不读 Key、不联网、不写库：

```powershell
node scripts/process-cached-activities.ts --input=.local-data/xian/runs/xhs-20261112-latest/normalized.json --output=.local-data/xian/runs/new-offline-audit --date=2026-11-12
```

缓存取自当前启用来源，最多选择十篇；所有小红书记录仍为未核实来源。当前实际缓存的五条输入已通过离线检查，API 调用为 0、events 写入为 0。

未来在两个 Key 配好并开始真实联调时，显式加 --live 才会调用 API：

```powershell
node scripts/process-cached-activities.ts --input=.local-data/xian/runs/xhs-20261112-latest/normalized.json --output=.local-data/xian/runs/new-live-check --date=2026-11-12 --live
```

只有再显式传 --publish-root=.local-data/xian/validated-releases 才请求生成独立发布库；零条合格活动不会覆盖旧批次。每次输出目录必须是新的，不能覆盖既有结果。过了 36 小时的旧缓存需要重新取得来源并核实，不把修改 fetched_at 当作重新采集。

活跃入口只处理正向活动候选。取消通知的可信匹配与发布函数已离线测试，但夜间自动发现取消通知及调度未接入。没有把这个命令宣传为可长期无人值守的成品。

## 6. 验收范围

已覆盖：模型重试与预算、结构化分流、提示注入边界、假证据和值不一致、取消/旧文/年份缺失、来源信任、主站佐证冲突、坐标歧义/范围/坐标系、缓存、写入去重、ID 补齐、发布前故障、坏 hash、取消及历史、时效先于 LIMIT、正文未变不能续期、发布前字段被篡改、真实时间跨异步请求推进。
