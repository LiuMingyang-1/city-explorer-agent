# 小红书活动采集：后处理与验收

更新：2026-11-12。**当前 demo 校验规则以 [Demo规则说明](collection-demo-policy.md) 为准；下文逐字引用、旧地址严格匹配等描述为上一轮实现记录，已被放宽。**

本文件按最新约定替代之前“所有社交帖子必须补查官方主来源”的规则。当前只启用小红书缓存处理；网页搜索及文本提取使用 DeepSeek，位置确认使用高德。其余平台、定时采集部署和正式库发布不在本次改动范围内。

## 1. 配置与数据边界

- `DEEPSEEK_API_KEY`：网页搜索和 `deepseek-flash` 提取共用。
- `EXPLORER_COLLECTION_MODEL`：提取模型名，不是第三套 API。
- `AMAP_WEB_KEY`：高德 Web 服务 POI 搜索及地理编码。
- Key、Cookie、原始帖子与真实 API 响应仅存本地忽略目录，不提交。
- 原 `events` 表保持18列，三个可空时间/时长字段继续默认 NULL。原始来源链接在 provenance 的 `source_url`，不把高德接口替换成活动来源；本次不迁移 `guide_url`。

## 2. 实际流程

```text
MediaCrawler缓存 → URL/hash/正文范围检查
  → DeepSeek提取（当前北京时间、首次发布时间、编辑时间、正文、schema）
  → 本地补充缺失原文引用；不支持的简介回退为原文摘录
  → 有条件补全年份，按日期计算可收录状态
  → 校验必填、价格、时长、日期冲突、取消和回顾
  → 高德确认唯一场馆、城市、地址及坐标
  → 最终复核，生成18列events、原帖provenance和时效metadata
  → 私有JSON验收；仅显式指定publish-root才发布实验数据库
```

模型仍使用 `active/cancelled/past/unknown`，其中 active 包含未来和展期内活动，不表示此刻正在营业。程序在 metadata 记录 `upcoming/within_period/permanent/unknown`，保留展期开始、结束日期。没有具体小时的记录只能用于发现，不能据此自动排日程。

原帖子可直接作为信息来源，`unverified` 表示未认证作者身份，不表示禁止入库。程序不得冒充其为官方账号。默认不发起主来源查询；历史主来源解析器保留为显式 `requirePrimary` 选项，普通运行入口不启用。

## 3. 提取与自动补全规则

1. 模型收到 current_time、Asia/Shanghai、published_at、updated_at、search_city、source_url、text 和 schema。搜索城市只是范围提示。
2. 模型负责多个活动的语义对应、分类、预告/取消/回顾判断。不能输出坐标、信任等级和发布许可。
3. 本地仅为确实出现在正文中的值补引用；生成简介不被引用支持时，改用原文片段。缺失费用不是免费，未知时长不估算。
4. 对“展览到11.29日结束”这类明确结束表达，首次发布不超过7天、无回顾/其他年份冲突、候选日期在发布日前1日至后120日内时，可按发布时间的上海时区年份补全。不仅凭编辑时间补年，不猜跨年。`11.29` 的模型输出也会标准化。
5. status 为 unknown 时，可按已引用的有效结束日期计算 active/past；取消与回顾先处理。明确常设展/长期开放可无结束日期，仍受缓存复查与保留期约束。
6. JSON格式错误或可修复的引用/日期格式错误最多再调用模型一次，所有调用计入总预算。反馈明确错误代码；不得靠编造通过校验。总调用预算用尽则拒绝，不无限重试。
7. 城市原文缺失或城市引用漏填不会在地图查询前直接丢弃；最终必须有有效高德行政代码和城市地址。其他冲突继续拒绝。

局限：补年当前只实现上述明确结束表达，不是任意自然语言日期解析器；不会把展期展开为每天开放，也没有通用节假日营业日历。常设展必须有明确文字，不能把任意“专题陈列”自动当永久开放。OCR、视频转写未实现。

## 4. 高德输入、匹配与输出

- 内部输入：venue_name、可空address、可选require_entrance。
- `/v3/place/text`：keywords 为清理楼层后的场馆名，city=西安、citylimit=true、page=1、offset=25、extensions=all、children=0。
- 保留分馆身份；只消除标点、末尾楼层/展厅和“馆区”拼写差异，不把东馆、西馆合并。
- 使用候选名称、城市、行政代码、区县及已有街道门牌匹配。模糊结果总数较大不单独构成拒绝；名称唯一匹配时允许没有原始地址。
- 已有门牌地址且模糊结果有分页时，调用 `/v3/geocode/geo` 核对完整地址，只接受精确级别且恰有一个点距POI/入口不超过500米。不是实地精度承诺。
- POI完全无结果时才启用完整门牌地址兜底；有候选但存在名称/地址冲突时继续拒绝，不擅自把旧地址改成候选地址。复杂别名、多入口和冲突消解仍有覆盖限制。
- 最终保存地点ID、标准地址、行政区、原始GCJ-02点、转换后的WGS-84坐标、转换版本、核验时间及必要的地址核对记录。需要入口而高德未提供时拒绝。
- 缓存键绑定原输入名称、地址和入口要求，有效期30天。请求限制体积、时间和次数，错误不回显含Key的URL。

地点证据来自高德，活动source_url仍是帖子或网页原链接。高德只能核对地点，不能证明活动举办或展期正确。

## 5. 时效、身份与发布

metadata 保留首次发现、最近核验、来源发布/编辑时间、展期和 `dateBasis`。补年区分 explicit、recent-publication-inference、unknown。只有重新抓取而未重新核验，不延长已核验时效；过期、取消不能靠重复抓取复活。无结束日期的记录仍受现有7天保留及36小时核验新鲜度约束，不无限保留。

现有身份登记保证相同source_event_key的重复更新和时间补全保留ID；跨来源不同标题的语义合并尚未实现，不宣称全平台去重已经完成。

实验发布仍经过原始资料和坐标绑定复核、SQLite副本upsert、完整性检查、原子CURRENT切换。正式应用默认读取的 `data/events.db` 本次没有修改。没有安装系统夜间任务。
