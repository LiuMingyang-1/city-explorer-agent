# 阶段 1 验收记录

验收日期：2026-11-12（Asia/Shanghai）。状态：离线搜索骨架与最小持久化已实现，测试通过；尚未开始阶段 2。

## 实际完成范围

- `src/search/` 提供独立 SearchService、请求/响应校验、渠道调度、命中规范化、结果分页与 SQLite 仓库。
- 使用 Ajv 8.20.0 的 2020-12 实现加载阶段 0 权威 JSON Schema，并补充业务不变量检查。依赖锁定在 package.json/package-lock.json。[Ajv Schema 版本说明](https://ajv.js.org/json-schema.html)
- 三张搜索表支持幂等初始化、事务写入、文档身份去重、稳定 ID、失败回滚及过期记录清理。所有测试使用内存库或临时文件库。
- 调度器共享全局及单渠道并发限制，支持截止时间、父取消、有限重试、Retry-After、排队退出，超时后不提前释放尚未结束的适配器槽位。
- 资料结果按渠道排名融合，返回来源及能力限制；没有生成可规划活动。不同完成顺序不会改变结果排序。
- 快照分页可以关闭重开后恢复；随机游标仅存哈希，绑定作用域、查询参数与有效期。响应控制 UTF-8 字节数，不静默丢弃已取得的后页结果。
- 模式未实现的行为明确披露：local 失败并说明，hybrid 执行外部假渠道并报告本地尚未接入；external 为本阶段完整路径。
- 搜索缓存复用、真实平台、正文获取、模型提取、活动发布与 source_url 迁移均留在后续阶段。

生产 CLI/Web/主 Agent 未接入新服务，现有唯一工具及其活动数组返回保持原状。没有运行 seed，没有修改实际活动或会话数据库，没有调用真实搜索平台或模型 API。

## 测试发现及修复

1. 阶段 0 response Schema 使用相对 `$ref`，其原 URN `$id` 无法由正式解析器正确解析。两个 Schema 改成同目录稳定 HTTPS 标识；它们只是标识，校验过程不访问网络，字段契约不变。
2. 原有测试的清理钩子按注册顺序执行，临时目录早于 SQLite 关闭被删除，Windows 报 EPERM。新增测试资源清理辅助函数，按资源取得顺序的逆序释放，并聚合清理异常；涉及的旧 fixture/测试改用该辅助函数，没有改业务逻辑。
3. 原有配置测试硬编码 POSIX 路径分隔符，改成 node:path.join 断言。
4. 原有静态服务越界测试创建文件符号链接，在当前 Windows 环境没有相应权限。改成 Windows 目录 junction、其他系统目录符号链接，继续验证真实根目录越界拦截，没有跳过安全断言。

## 已知边界及实现细化

- 渠道注册与路由目前合并在 service.ts 中，未为简单逻辑额外拆 registry.ts；接口仍支持新增独立适配器。
- 游标状态增加 scope_key/cursor_state_json 两个字段，仅涉及搜索表；完整目标 DDL 的后续活动表及 events ALTER 未执行。
- SearchResponse 单页受 schema 最大 50 条限制；内部快照可保存更多已取得资料，外部通过游标分批获取。搜索请求受每渠道最多 2 页和总命中配额限制，上游截断会显式披露。
- 阶段 1 没有全文快照文件，不伪造正文哈希；response_json 冻结本次可返回资料，正文快照属于阶段 2/5。
- 适配器必须遵守取消信号。忽略取消的适配器会继续占用槽位，close 等待它实际结束；不能保证强制终止任意第三方代码。
- 存储故障会抛出 SearchStorageError；连审计更新也失败时不能保证落盘有完整失败记录，原始失败仍向调用方暴露。
- 当前输出全部是未经活动事实校验的资料，city_status/date_status 为 unknown，不承诺适合某天参加，更不能直接进入行程。
