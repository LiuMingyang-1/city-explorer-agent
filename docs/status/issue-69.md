# #69 首访优先高德与可诊断回退

2026-11-17（Asia/Shanghai），从最新 `main@8e16a04` 建立 `fix/69-amap-startup-fallback`，仅处理本 issue。

## 已确认的根因

旧版 `frontend/amap.js` 在 `isDOMMode()` 或 `baseRender === 'd'` 时直接销毁已经创建的高德地图并返回 false。DOM 是 SDK 的兼容渲染路径，不等于高德不可用。旧版同时强制 `forceWebGL`，并对部分 Safari 屏幕信息作临时替换；这些内部兼容性干预现已移除，让 SDK 选择实际可用的渲染模式。

实际对照使用相同配置、真实 JS API 2.0、Linux Chromium 156.0.8078.79：禁用 WebGL 时，旧主分支记录到 `destroy({dom:true, baseRender:'d'})`，随后显示 OSM 栅格地图；修复版保持高德 DOM 地图、原生归属信息和一套缩放控件。该路径已复现；不能据此断言所有用户的回退都来自同一原因，更没有证据将问题归因于缓存。

旧版还把全部搜索/天气插件与所有预置景点坐标转换放在底图初始化的必经路径。现在底图先启动，可选依赖失败只降级对应功能；相关故障由定向测试注入验证，未冒称为真实线上故障。

保留备用地图的验证中还实际发现：MapLibre WebGL 构造失败会留下半挂载的 Leaflet bridge，其原 `onRemove` 访问不存在的 renderer，导致缩放监听不能正常解除，后续 `flyTo` 抛出 `jumpTo` 异常。修复为先持有图层引用、对未构造 renderer 的移除作清理，确保 OSM 可以继续平移缩放。这属于本次回退链路修复。

## 改动

- 配置请求不使用浏览器缓存，每次请求限时 12 秒，瞬态失败有一次有界重试；服务端仍使用 `Cache-Control: no-store`，禁用时返回不含密钥的缺失配置类别。
- SDK 与插件独立加载。SDK 网络错误重试一次；SDK 等待 20 秒后可进入备用地图，迟到脚本不会自行创建地图。显式重试可复用加载完成或仍在加载的同一脚本。
- 保留高德 DOM 模式并显示“兼容渲染模式”。兼容栅格底图标签较密，不能保证与 WebGL 自定义样式完全一致；支持的 WebGL 模式继续使用原样式参数。
- 西安默认中心采用仓库 `src/collection/coordinates.ts` 算法导出的固定 GCJ-02 对应值，保留原始 WGS-84 坐标元数据。只有这个已知默认中心免去启动网络转换；景点、定位、路线仍走现有转换入口，不把 WGS-84 直接标记为 GCJ-02。
- 景点转换和工具栏在后台加载，搜索、逆地理编码、天气按需加载插件；失败不会销毁可用底图。
- 保留 OpenFreeMap 与 OSM 栅格兜底。持久的提供方/原因提示与临时消息分开，瓦片加载完成不会清掉回退说明；提供“重试高德”。
- 重试单次在途执行，配置/SDK 加载期间保留可用备用地图。创建高德前才释放 Leaflet、图层、定时器及活动请求；恢复原地点、视野及当前方案。所有异步结果有代际检查，旧配置、转换、图层回调不能写入新地图。
- 诊断入口为 `window.WanderMaps.diagnostics`，包含 attempt、stage、固定 code、level、时间与备用渲染原因；不记录 URL、请求参数、上游报错正文、JS key 或安全密钥。
