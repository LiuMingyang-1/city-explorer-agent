# #67 地点标签发送后的清理

2026-11-17（Asia/Shanghai），独立分支 `fix/67-required-itinerary-event` 从最新 `main@8e16a04` 创建。

用户本轮澄清“只是需要把这个清理掉”，因此本次限定为前端标签清理，不接入模型、不修改后端请求契约或规划校验。原 issue 中“加入行程作为必去地点”的后端语义并未在本提交实现，不将本次交付描述为已完成该项校验。

旧逻辑直到 `deliver()` 的 `finally` 才清理标签，请求过程中标签持续显示。现在仅在接受发送后立即清理输入区，并先保存标签快照供本轮和失败重试使用；请求完成时不再清理草稿。新聊天的既有重置行为保持有效。更新聊天脚本版本参数，避免浏览器继续复用旧资源地址。

验证：

- `npm run check:frontend` 通过；`npm run check` 类型检查及 1029 项测试通过。
- 新增 5 个异步回归，覆盖无文字直接发送、补充文字、下一轮不携带旧引用、JSON/SSE 失败重试、保留新草稿和新聊天隔离。
- 实际 Chromium UI，1440×900 与 390×844：点击地图气泡→详情→加入行程→发送，在响应尚未返回时标签已经隐藏；请求仍携带原 `referenced_event_id`。
- 发送期间通过详情按钮加入另一地点，故障响应后重试仍使用原地点，草稿标签和文字保留；随后发送新草稿携带新 ID，下一条普通消息不携带地点引用。
- 浏览器检查使用受控活动、地图瓦片和聊天响应；桌面覆盖 JSON 错误，手机覆盖 SSE 错误，未捕获异常均为 0。没有调用真实模型，也不据此证明模型会强制纳入地点。
