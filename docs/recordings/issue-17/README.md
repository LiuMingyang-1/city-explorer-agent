# #17：手动拖走地图后，点击方案卡片重新定位路线

基于 `main@c993f38` 创建独立分支 `fix/17-plan-route-refocus`，只处理 #17。

## 原因与改动

最新主分支中，新生成的方案已经会在打开卡片时定位。但恢复历史规划时，`WanderHistory.open` 使用 `append(plan, {drawMap:false})` 延迟首次绘图，等待地点恢复后再绘制路线。该参数被卡片的整个 `choose` 生命周期捕获，后续打开预览、点击 A/B 都跳过绘图，造成“第一次能定位，再点卡片无反应”。

修复将 `drawMap:false` 限定为初次装配；每次主动打开卡片、重新点击同一方案或切换 A/B 都按当前方案重新绘制并取景。没有在拖动事件中增加任何自动定位。

路线取景同时考虑已展开的活动详情和记忆面板。高德和 Leaflet 共用可见区域计算：保留左侧卡片边距，在面板之外选择最大的矩形区域，紧凑窗口可使用面板下方空间。没有面板时仍保持原来的取景中心和边距。

浏览器：Chromium、1440×900、真实高德 JS SDK 2.0。测试记录每次 `setFitView` 调用，并检查选中方案的停留点及道路几何投影是否全部处于可见取景区域。每次手动拖动都确认地图中心变化，等待后确认没有新增取景调用；随后点击卡片才重新定位。详情展开时，路线取景避开左右卡片。

浏览器记录：恢复历史后，修复前点击卡片的 `setFitView` 调用次数保持 `3 → 3`，路线仍在取景区域外；修复后为 `3 → 4`，相机动画结束后全部路线点回到可见区域。重复 A、选择 B、重复 B 分别触发第 5、6、7 次取景；右侧详情展开后为第 8 次，再次打开预览为第 9 次。浏览器没有未捕获的 JS 异常。

测试边界：该环境中高德矢量底图请求返回 403，SDK 报 `FlyDataAuthTask error: param version not valid`，所以录屏背景缺少道路底图；方案路线、SDK 投影、拖动及相机取景仍实际运行。本次没有修改底图鉴权。Leaflet 通过回归测试验证，未使用 Leaflet 录屏。

## 人工复测

按 [高德接入说明](../../integrations/amap.md) 配置本机环境并运行 `npm run dev:web`。可使用现有联调 mock 响应：

1. 生成 A/B 方案，确认首次定位。
2. 将路线拖离可见区域，点击方案预览找回。
3. 返回对话，新聊天，再从历史列表打开该规划。
4. 再次拖走地图并打开方案预览；重复点击当前 A、切换 B、再次点击 B，分别检查路线定位。
5. 展开右侧活动详情，点击方案，检查整条选中路线避开卡片；手动浏览后不应被自动拉回。
