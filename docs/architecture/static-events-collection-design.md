# 西安市静态活动数据采集实施设计

更新：2026-11-12。当前社交来源仅小红书；阶段 3–5 核心已实现并进行离线验收。最新实现与限制见 [后处理设计及验收](collection-downstream-design.md)。历史平台调研保留，其他平台运行入口已禁用。

本文件承接用户最终约定，作为后续实施依据；与旧采集规划冲突时以本文为准。工作分支为 `feat/xian-nightly-events`，不合并主分支、不推送密钥。当前任务是夜间补充本地活动库，不开发面向主 Agent 的实时外部搜索。

> 2026-11-12 范围调整：用户取消知乎，当前启用小红书、抖音、快手、B站、微博、贴吧六平台，网页仍为 DeepSeek。知乎历史适配保留但不参与登录、搜索或新导入。

## 1. events 字段契约

保留现有 18 列、列名及业务含义。采集候选与最终可发布活动是两个不同契约；不完整候选只放临时文件，不提前写 events。

| 数据库字段 | 类型与目标默认值 | 是否可空 | 最终发布要求 |
| --- | --- | --- | --- |
| id | TEXT PRIMARY KEY，无默认 | 否 | 本地生成稳定 ID，唯一且不随描述更新而变化 |
| title | TEXT，无默认 | 否 | 明确的具体活动名称，去除平台营销噪声，不改活动身份 |
| description | TEXT，无默认 | 否 | 有依据的介绍，不生成未经确认的特色、开放情况、余票 |
| category | TEXT，无默认 | 否 | 必须为下文固定枚举之一，无“其他”兜底 |
| venue_name | TEXT，无默认 | 否 | 明确场馆及必要分馆/门店/入口信息 |
| address | TEXT，无默认 | 否 | 确认到具体举办地点，原文不足时可用已确认的地图地址补全 |
| latitude | REAL DEFAULT NULL | 是 | 候选允许缺失；最终发布必须有已确认的有限数值 |
| longitude | REAL DEFAULT NULL | 是 | 与 latitude 同时有值或同时为空；最终必须补全 |
| start_at | TEXT DEFAULT NULL | 是 | 上海本地时间 YYYY-MM-DDTHH:MM；未知为 NULL |
| end_at | TEXT DEFAULT NULL | 是 | 同上，不默认闭馆、散场时间 |
| suggested_duration_minutes | INTEGER DEFAULT NULL | 是 | 已确认的正整数分钟；未知为 NULL，不写规划估计 |
| budget_min | INTEGER DEFAULT NULL | 是 | 单人金额下限，单位分；明确免费为 0，未知为 NULL |
| budget_max | INTEGER DEFAULT NULL | 是 | 同上；都已知时 min <= max |
| currency | TEXT DEFAULT 'CNY' | 否 | 当前仅人民币 |
| budget_note | TEXT DEFAULT NULL | 是 | 票种、费用范围、预约及费用解释，必须有依据 |
| guide_url | TEXT DEFAULT NULL | 是 | 本轮保留原列名；没有真实攻略则 NULL，不塞地图接口或密钥 |
| thumbnail_url | TEXT DEFAULT NULL | 是 | 已取得的公开图片链接，未知为 NULL |
| image_urls | TEXT DEFAULT '[]' | 否 | 数据库存 JSON 字符串数组；JSON 交付对象用数组 |

“可空且有默认值”明确为 SQL `DEFAULT NULL`。写入端还需将缺失键规范化为显式 null；SQL 默认值只在省略列时生效。不用空字符串、0 分钟或虚构时间代替未知值。三个时间字段均无业务兜底值。规划器如需估计停留时间，在规划侧计算并说明，不回填本表。

数据库约束目标：category NOT NULL + CHECK 枚举；非空文本禁止纯空白；经纬度合法范围、成对可空；时长为 NULL 或 1–1440 的整数；费用非负整数及区间检查；image_urls 是 JSON 数组。来源真实性、坐标匹配、时间格式等跨资料检查由发布校验完成，不能声称 SQL 能验证事实。

### 1.1 分类枚举与归类顺序

固定 12 类：`展览`、`音乐现场`、`演出`、`市集`、`节庆活动`、`书店活动`、`讲座`、`工作坊`、`放映`、`景点参观`、`户外活动`、`体育赛事`。

- 按活动主要内容分类，不按承办场所：书店里的展览归展览，明确讲授内容归讲座。
- 音乐演唱/演奏现场归音乐现场；戏剧、舞蹈、脱口秀等归演出；电影放映归放映。
- 书店活动用于读书会、签售等阅读主题活动；参与式制作/技能体验归工作坊。
- 市集、节庆活动、体育赛事按主体判断；普通徒步和户外体验归户外活动。
- 景点参观必须是具体可定位地点，当前开放/参观依据与有效期能核实；不把城市攻略文章本身当活动。
- 综合内容无法选定一个主要类别时，先尝试拆成有独立依据的活动；仍无法判断则拒绝。

代码实施时使用一个分类常量生成/校验 SQL、JSON Schema 与模型枚举，防止三份列表漂移。不要自动把旧库未知类别改成“其他”；迁移前报告不兼容行并停止该次迁移。

### 1.2 时间与身份

- 一行对应一个活动在一个地点的一次明确场次或一个开放时段。开放多日且每天闭馆的活动按已确认开放日逐日展开，不把整个展期变成连续 24 小时开放。未知休息日不自行补排。
- 两个边界独立允许 NULL；都已知时结束晚于开始，时长不能超过窗口。跨午夜按真实日期表达。当前发布契约采用单个时段不超过 24 小时，多日开放规则另存来源元数据后展开；须修订旧文档“任意跨多日窗口”的冲突描述。
- 固定演出有官方时长时可确定性计算结束时间，标记 derived 并保存计算依据；没有依据不按类别猜散场。窗口长度不是建议停留时长。
- 缺任一时间边界仅可用于发现，不自动排日程；缺建议时长但窗口完整可交规划侧估计。
- 活动展期、确认结束日期、日常开放规则放元数据，不把它们伪装为某场 start_at/end_at。
- ID 必须经过身份登记再分配：优先匹配平台内容 ID/主办方活动 ID、场馆分馆和场次。旧候选从未知时间补成已知时间时复用身份，不重新按新时间哈希制造重复；明确新增场次才产生新 ID。仅名称相同不足以合并。

## 2. 搜索覆盖与采集边界

已确定技术选型：MediaCrawler 负责六平台；DeepSeek 负责网页搜索和定向补查；deepseek-flash 负责需要语义理解的文本提取。不使用 Qovia，不引入其他按次收费社交搜索服务。

| 来源 | 重点内容 | 处理注意 |
| --- | --- | --- |
| 小红书 | 展览、市集、体验活动、主办方笔记 | 区分推荐攻略与实际举办信息，海报单独处理 |
| 抖音 | 本地演出、节庆、场馆发布 | 视频上传日期不等于活动日期，描述不足不能硬填 |
| 快手 | 本地节庆、演出、主办方动态 | 同样检查地点、年份及原发布者 |
| B站 | 场馆公告、展览介绍、活动预告 | 排除往届回顾、录播及纯游记 |
| 微博 | 主办方公告、调整与取消信息 | 保留原帖与转发关系，转载不算独立验证 |
| 贴吧 | 本地活动线索、场馆/社群公告 | 普通帖子仅作线索，需补查可核实活动依据 |
| 知乎（已取消） | 不参与当前采集 | 保留历史适配，不进行新登录、搜索或导入 |
| DeepSeek 网页 | 主办方、文旅、场馆、票务详情及取消公告 | 搜索命中只作发现，取可追溯正文，不用摘要直接发布 |

MediaCrawler README 列出上述七平台关键词搜索支持，但不代表本机所有启用平台已验收。固定一个通过验证的 commit，以外部 Python 进程运行；本项目只消费其导出数据，平台专属字段由适配器转换。登录态、浏览器数据和源导出均在忽略目录。初次登录单独处理；夜间登录失效记 login_required 并停止该平台，不弹窗、不绕过验证。README 的学习用途和禁止商业用途限制仍适用。

关键词由“西安 + 分类/别名 + 近期日期词”组成，并补充已知场馆、主办方账号；城市归属最终依据举办地址和地图核对，不依据发帖 IP。覆盖不承诺全量。

### 2.1 小样本与扩量

- 工具连通样本：每平台 2 个关键词，每关键词最多 5 条唯一内容，六平台上限 60 条；DeepSeek 选 6 个定向查询，每查询最多保留 5 条命中，上限 30 条。未搜索成功的平台如实记失败，不用网页结果冒充该平台成功。
- 内容验收样本：在上述结果中按分类与资料形态分层检查；不要求人为凑满活动数，不因通过率低放宽门槛。
- 全流程样本：最多 10 条通过内容检查的活动进入坐标查询和试写；先输出临时批次与验证报告，不修改现用正式库。
- 通过后再扩至未来 14 天活动；初次资料回看 30 天。具体每日配额由实测耗时、平台状态和 API 预算决定，不能凭设计承诺搜索延迟。

## 3. 处理模块与本地/模型分工

```text
夜间入口（锁、预算、成功水位）
  ├─ MediaCrawler：六个平台独立任务 → 平台导出适配器
  └─ DeepSeek 网页搜索 → 正文获取器
           ↓
统一 SourceDocument → 清洗、内容哈希、去重、粗筛
           ↓
结构化直提 / 模型提取 / 图像文字提取后再理解
           ↓
候选活动 + 字段证据 → 内容与时效检查
           ↓
场馆身份匹配 → 高德 POI / 地理编码 → 坐标核对与转换
           ↓
最终发布校验 → 去重与身份登记 → 批次写入、发布
```

### 3.1 统一原始文档

SourceDocument 最少保存 provider、platform、source_id、canonical_url、作者/机构标识及其可核实依据、title、text、image_urls、published_at、updated_at、fetched_at、content_sha256、原始导出文件引用。未知时间为 NULL；发布时间、编辑时间、抓取时间分别存储。记录内容范围和是否正文完整，不用平台粉丝数推断来源真实性。

直提字段：内容 ID、链接、采集时间、平台明确返回的发布时间、正文和图片 URL；已有可信 JSON-LD/结构化活动字段优先直接解析。日期格式、单位换算、ID、哈希、URL 处理、去重和规则校验由本地执行。

需要模型的任务：长文本中的活动归属、混合日期/地址理解、多活动拆分、分类、事实摘要、取消与变更语义。模型只能引用输入资料，允许 abstain；输出未知字段为 null，不调用额外工具自行补事实。非结构化候选不以正则兜底发布。

图片信息：先用可验证的本地 OCR 获取文字；文本不足或版式关系有歧义时，需要另行验证视觉能力。deepseek-flash 当前仅承担文本理解，不假定可以直接看图。视频仅有标题/简介而无关键事实时，本阶段拒绝；音视频转写不是首轮依赖。

网页/帖子是资料，不是系统指令。忽略资料中要求改规则、执行命令、读取凭据或跳过校验的文字。模型无数据库写权限。

### 3.2 模型输出与证据

每次输出 candidate 列表，每个 candidate 包含 18 列目标字段、schedule_type（window/fixed/unknown）、确认活动有效期、source_refs、字段 evidence、conflicts 和 extraction_status。坐标默认 NULL，不请求模型生成经纬度。

evidence 对关键非空事实记录 document_sha256、source_url、原文片段、定位信息和 origin（direct/model/derived）。派生结束时间/分钟换算还需记录输入字段及公式。分类记录支持内容与分类规则；摘要只能重述已证实事实。地图补全的地址以地图响应为证据，不强制它在帖子原文出现。

本地验证模型 JSON 结构、字段类型、原文片段存在性、文档哈希和派生公式。片段存在不等于事实已验证；模型自报 confidence 不作为放行条件。结构错误最多重试 1 次，缺事实最多定向补查 1 轮；仍不满足则拒绝，不无限修复或自动切换昂贵模型。

## 4. 高德坐标确认方案

采用场馆缓存优先、POI 搜索为主、详细地址地理编码为辅。需要服务端高德 Web 服务 Key；Key 只从本地环境读取，不能写入 URL 日志、元数据或提交文件。额度、价格及结果持久化条件在接入前按账号和服务条款核实，本文不承诺免费。

1. 活动内容合格后，规范化“西安市 + 区县 + 场馆全名 + 分馆 + 道路门牌”；不能删掉关键分馆信息。缓存键包含这些身份信息。
2. 缓存仅复用已确认且未过核验期的场馆，初值 30 天；来源出现迁址、同名新分馆或地址变化立即失效。缓存遵守服务许可的存储条件。
3. 未命中调用 POI 关键字搜索，显式 city=西安、citylimit=true；对返回 city/adcode 及目标行政边界再次核对。不能只靠城市前缀或粗经纬度矩形判断行政归属。
4. 比对官方名称/已确认别名、区县、分馆、道路及门牌。必须有唯一、无冲突匹配；排序第一或只有一个结果都不自动代表正确。模型可辅助整理名称，不负责签发坐标通过结论。
5. 无合适 POI 时使用完整详细地址地理编码。只接受能确认到具体门牌/建筑/场馆的结果；城市、区县、街道、道路中心点一律拒绝。核对接口实际 level 返回值再建立允许列表，未识别值默认拒绝。
6. 室内活动优先具体分馆/建筑/可达入口；大型景区、园区不能随意用整个区域中心点代替场地。户外活动需明确集合点；路线与多站点本阶段不压成一个虚假地点。
7. 必要时逆地理编码复核行政区和地址；它仍是同一服务，不作为独立第三方佐证。信息冲突时补查主办方场馆说明，无法消除则拒绝。
8. 保存 POI ID、查询输入、脱敏请求参数、原始坐标与坐标系、匹配地址、行政编码、核验时间、转换版本和结果；不要把含 key 的请求 URL 当 source_url。

### 4.1 坐标系与精度验收

当前前端为 OpenStreetMap/OpenFreeMap，当前最终契约为 WGS-84，继续保持统一。高德结果为 GCJ-02，禁止直接标成 WGS-84 入库。

转换模块与服务调用分开，候选实现参考 eviltransform 的反向转换；固定版本，测试已知样本、经纬度顺序、往返残差及地图落点，并保存原始坐标。往返测试只能验证转换一致性，不能证明实际定位精度。不能把项目宣称的算法误差当作 POI 的现场测量精度。

坐标验收目标是正确场馆/分馆及可达入口，不承诺测绘级精度。上线前用至少 5 个可独立核对地点检查分馆、门牌及图面落点；没有独立参照不得宣布实测精度。若转换与数据使用条件无法满足，坐标阶段停止，不混入坐标系，也不擅自修改前端。

## 5. 校验、舍弃与时效

| 层次 | 放行条件 | 失败处理 |
| --- | --- | --- |
| 文档 | 有来源身份、链接、可用正文，内容范围可追溯 | 摘要不能替代正文；获取故障按技术失败处理 |
| 真实性 | 能证明是具体活动/可参观地点，举办信息可核实 | 普通用户帖子作线索，补查主办方/场馆/可靠票务依据；转发不算独立核验 |
| 结构 | 必填非空、分类有效、可空字段显式 null、无额外字段 | 结构重试后仍失败则拒绝 |
| 事实 | 非空事实有证据，计算可复现，关键来源无未解决冲突 | 同一发布方明确更新优先；跨来源无法解释的日期/地点冲突则拒绝 |
| 时间 | 日期时钟合法、窗口顺序正确、时长与费用关系正确 | 禁止默认年份、按上传日猜活动日；不合格则拒绝 |
| 有效性 | 已取消/结束排除；缺时间也有近期有效依据 | 仅“刚抓到”不通过；无有效性依据则拒绝 |
| 地点 | 西安市内、场馆唯一匹配、坐标和坐标系已确认 | 最终缺坐标或歧义则拒绝 |
| 身份 | 同场次跨平台归并、稳定 ID，新增与更新可解释 | 无法安全判断时不覆盖已有记录 |

允许三个时间字段为空，不意味着允许活动有效期完全未知。元数据至少说明有效性证据和核验日期；固定场次缺时间可保留为发现记录，但不能排日程。时间未知记录从首次发现最多保留 7 天；文档发布时间超过 30 天且无当前有效依据则拒绝。明确的长期景点需有当前开放依据，不能只套用一篇旧攻略。

首次发现、最近抓取、最近事实核验分开；相同哈希的重复抓取不刷新事实核验。已验证超过 36 小时的记录先退出推荐集合，优先复核未来 14 天内容。官方页面原文未变只能确认页面状态，不能独自证明没有别处发布取消公告；复核需包括可用的更新/取消渠道。阈值均为待小样本校准的初值。

语义上不合格的候选直接舍弃，不写 events、不建长期待人工核对队列；只留脱敏来源 ID、内容哈希、拒绝原因及运行统计。原始样本按短期调试留存策略管理。登录、限流、超时是技术失败，允许有界重试，不能推断活动取消或删除已有活动。

行级拒绝不能拖垮整个批次；批次级契约错误、发布一致性错误则全批不发布。一个来源失败不影响其他来源采集，但报告必须显示缺失覆盖；新库不能用空批次替换旧成功库。

## 6. 夜间执行、存储与发布

目标每晚 Asia/Shanghai 02:00 静默执行，目前不安装任务。六平台独立登录态、配额、错误状态和成功水位；关键词搜索未必支持严格时间过滤，水位仅代表成功处理状态，不能当成平台增量完整性的保证。每次至少回看 48 小时并按来源 ID、哈希去重。

单机互斥锁；每平台并发初值 1，全局平台任务并发初值 2，后续按实测调低或调整。限流指数退避，单请求最多 2 次重试；来源级超时和全局预算触发后停止新任务，不推进失败水位。具体超时在连通样本测量后配置。

本地私有工作目录使用 `.local-data/xian/`：

```text
runs/<run_id>/       原始导出、规范化文档、候选、拒绝日志、延迟统计
state/              来源水位、内容缓存、场馆缓存、身份登记
releases/<batch_id>/ events.db、provenance.json、manifest.json
CURRENT             已验收批次指针
```

来源、核验、状态、坐标与证据保存在 provenance sidecar，不增加 events 列。采集器内部状态和主 Agent 隔离，Cookie/Key 不进入发布包。元数据修订需升级契约：拟采用 xian-events/3，兼容策略在阶段 1 明确，不让 v2 校验器静默接受新语义。unknown schedule、unknown duration 和新增类别必须同步修订，不能沿用现有 window/fixed、source/estimated 必填枚举硬凑。

采用批次快照发布：通过 SQLite 一致性备份生成上一成功库的工作副本，在副本中短事务 upsert 合格数据，保留稳定 ID 与历史行；再写 sidecar、manifest（批次 ID、规则/模型/采集器版本、文件哈希、计数与覆盖状态），关闭写连接并验证全套文件。全部成功后以同盘原子替换 CURRENT 切换批次；失败不切换。备份使用 SQLite 支持的方法，不直接复制活跃 WAL 数据库主文件。

读取端后续需要支持 CURRENT：新请求取得同批次数据库与 sidecar，既有请求结束再释放旧句柄；切换失败继续旧批次。有效发现/规划 ID 集合应用 freshness 决策；getByIds 保留历史回查并说明失效状态。原始 SQL 对 date 的 NULL 过滤不能代替有效性检查。此读取适配是发布阶段的必要工作，完成前只导出试验批次，不能宣称已接入正式服务。

过期/取消记录退出推荐，不物理删除仍被历史引用的行。再次采到旧文章不能复活已取消场次。明确纠正取消状态需要可核实的新通知及新核验记录。

## 7. 延迟与质量报告

逐来源记录搜索、正文、模型、POI、转换、校验、写入各阶段时间；分冷启动/登录和正常缓存运行。报告样本数、成功/失败数、p50/p95、重试次数、模型调用/token、地图请求与缓存命中率、总耗时和峰值并发。小样本不足以推断稳定 p95 时明确标注，不沿用旧 Qovia/DeepSeek 试验耗时冒充七平台实测。

质量统计使用明确分母：唯一文档数 → 活动候选数 → 内容通过数 → 坐标通过数 → 最终发布数；另列拒绝原因、未知时间比例、发现可用数和可排程数。搜索无命中、平台失败、文档被拒绝分开统计。
