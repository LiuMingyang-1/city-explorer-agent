# 景点A级等级搜索工具

分析模型新增search_scenic_level工具，用于补查景点官方1A—5A级旅游景区等级。沿用DEEPSEEK_API_KEY，模型仍为EXPLORER_COLLECTION_MODEL；没有新增服务商、API Key或events表字段。活动分类保持原值，查不到的景点继续使用“等级未知”。

## 流程

1. 模型根据正文、OCR与高德地点判断对象是否为景点。原资料没有可靠等级时，可以用正式景点名称调用search_scenic_level。
2. 工具调用现有DeepSeek网页搜索接口，每次最多返回3份资料、每份最多6000字符，优先文旅部门名单、公告和景区官网。工具只补查等级，不用搜索内容覆盖原帖的时间、价格等事实。
3. 主分析模型提出等级及evidence.scenic_level_source。程序检查来源是本次工具实际返回的URL；原资料已经明确的等级也可作为核验输入。不是把等级对应的数字从任意评分中提取出来。
4. 有明确等级提议时，用同一个DeepSeek Key和模型进行一次专门的语义核验：确认等级属于这个具体对象、来源可靠且不是拟评定或已撤销的等级。子公园、子博物馆不能继承组合景区等级。
5. 本地检查返回枚举和网址、材料是否包含对应A级写法。兼容5A、五A级、AAAAA表格等表达。无法确认、空结果、接口错误或预算用尽时回退“等级未知”，不因此删除对象。

主分析最多5轮，地图和等级工具合计默认最多6次调用，每份资料最多3次等级搜索；一个提取器实例默认最多10次等级搜索和10次专门核验，scenicSearchLimit可调整。相同景点的搜索结果和相同核验输入在本次实例内缓存，下一批实例不继承旧缓存。

等级搜索和核验的API原始响应、网址及判断说明保留在本地诊断文件和提取witness中；guide_url仍是原帖子或原网页，不替换为补查等级的网址。上述预算不代表每条景点必然增加一次搜索和一次核验，原资料及缓存可减少调用。
