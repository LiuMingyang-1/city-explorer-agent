## 不等后端即可演示

```sh
npm run dev:frontend
```

访问下列地址，输入任意需求并发送：

| 地址 | 内容 |
| --- | --- |
| http://127.0.0.1:5173/?mock=comparison | 双方案 + SSE 阶段；切 B 后继续发送保留 B |
| http://127.0.0.1:5173/?mock=single | 单方案 B |
| http://127.0.0.1:5173/?mock=partial | 轨迹查询失败、通勤待确认 |
| http://127.0.0.1:5173/?mock=clarification | 追问 |
| http://127.0.0.1:5173/?mock=error | 规划失败与重试 |

所有样例直接来自 `docs/mocks/day0/`。开发服务器只通过 `/__mocks/day0/` 暴露预先列出的 JSON/SSE 文件，不复制一套易漂移的数据到前端。演示中的 SSE 阶段按样例短暂停顿播放；真实模式按服务器事件到达即时更新。当前演示明确标识“示例行程 · 非真实活动”。

不带 `?mock=` 时默认调用同源 `/api/chat/stream`；旧 JSON 服务可通过 `WANDER_CONFIG.chatEndpoint = "/api/chat"` 配置。开发静态服务器不提供真实 Agent 接口，真实对话需要由后端同源托管。页面配置也可显式设 `window.WANDER_CONFIG = {mock:'comparison', mockBase:'/__mocks/day0/'}`，仅供静态演示部署；代码中不放密钥。

## 如何与现有接口衔接

- 原有 `{kind:'itinerary', itinerary, events}` 继续显示完整活动卡。没有 legs 时只画活动点，不编造道路轨迹与通勤时间。
- 原有 `{kind:'clarification', question}` 继续显示文本追问。
- 样例 `{kind:'plans', plans, events, active_plan, coordinate_system}` 进入新组件。每条计划使用 `plan_id`、`itinerary`、`legs`，按 `event_id` 关联活动。
- 本次不依赖 `schema_version`、`revision`、`base_revision`、`request_id` 等扩展字段，也不发送这些字段。
- 收到 plans 后续聊增加 `active_plan`。地图活动提问在用户确认发送时带 `referenced_event_id`；用户改写草稿或开启新对话时清除引用，模拟活动不发送真实事件引用。主分支已支持这两个字段。
- 默认 `/api/chat/stream` 接收 SSE，仍兼容服务返回 JSON。可显式配置其他同源聊天端点。
- `progress` 只更新等待区，不保存为正式聊天消息；只有完整的 `result` 提交方案。`error` 或没有最终结果的断流保留旧方案并显示错误，不提交半成品。
- 新聊天/历史切换会 abort 客户端请求，并隔离迟到回复。历史保存当前激活方案，恢复时重新显示卡片和路线；演示和真实模式的本机历史分开。

## 坐标与路径

未配置高德时，底图为 OpenFreeMap / OSM 的 WGS-84；配置后使用高德并在入口转换。当前主分支样例与近期活动接口使用 GCJ-02，原生高德直接绘制。GeoJSON 顺序为 `[lng, lat]`；外部 WGS84 轨迹仍支持通过官方转换。

若真实响应已是 GCJ-02，OSM 模式会避免直接画错位置；高德模式已支持原生 GCJ-02 及 WGS-84 转换。不能只改坐标系字符串。

`legs[].geometry` 缺失或 `status !== 'ok'` 时只显示站点，路段显示“通勤待确认”。有效轨迹按原有坐标点逐段绘制，A/B 保留各自颜色，切换时自动聚焦当前方案的站点与道路范围，另一条路线保留半透明对比。

## 代码入口

- `frontend/plans.js`：数据适配、活动卡、A/B、通勤与地图轨迹。
- `frontend/transport.js`：JSON/SSE 接收、显式 Mock 入口、流式错误处理。
- `frontend/chat.js`：发送、阶段文案、新聊天取消、既有 API 兼容。
- `frontend/history.js`：本机历史、激活方案持久化与恢复。
- `test/frontend-plans.test.ts`：价格、图片失败、轨迹、A/B、请求兼容、历史、SSE 与 Mock 接入。

## 验证边界

自动检查覆盖真实样例结构、绘图调用和网络数据解析，不替代浏览器视觉验收。已配置预览站点高德 JS Key 并验证地址/坐标转换/天气服务；没有调用实际路径规划服务，样例仍不是可执行出行计划。

## 高德提供方补充

现已加入由环境配置启用的高德 JS API 2.0 提供方。`plans` 可以绘制 WGS84（经官方转换）或 GCJ-02（直接使用）路径；无高德配置的 OSM 模式仍拒绝错误坐标系。仅切换地图并不代表后端已经提供真实算路数据，Mock 活动和路线仍显式标为示例。

## 方案详情与地图活动预览（2026-11-12）

- Agent 返回方案时，对话中只显示一张紧凑的行程入口卡。点击后，详情覆盖左侧整张玻璃卡片，顶部提供「返回对话」；A/B 切换与地图高亮、`active_plan` 和历史记录保持联动。返回不会清空对话或改动选择；新聊天会退出详情。
- 右上角活动详情独立于左侧方案页：地图活动气泡按活动名称与场馆合并每日重复场次，点击后显示封面、活动说明、场馆地址、开放时间、每人预算及原站/数据来源。同场馆的活动可切换。「问问这个活动」只填入输入框，由用户确认发送。
- 地标点击展示 2.5 公里内已收录活动；没有数据时显示空状态。路线活动点也可打开对应详情。不会把没有活动的景区编造成有演出/展览。
- `frontend/data/demo-events.json` 由 `npm run mock:events -- --date=2026-11-13` 从现有种子模板导出，共 119 条、16 个场馆，保留分为单位的费用，并遵守当前主分支 GCJ-02 契约。导出不会读写开发者的 SQLite 数据库。省略日期时按北京时间今天生成。
- 种子中的 `example.com` 图片/链接是占位资源；演示使用本地示意配图，链接指向 GitHub 中的种子数据来源，明确标注模拟场地/排期。配图来源见 `frontend/assets/demo/SOURCES.md`。
- 默认读取已合入的 `/api/events`，默认坐标 GCJ-02；仅接口不存在（404）的独立前端开发环境回退到本地演示 feed，其他服务错误不伪装成真实活动。预览站点显式配置本地演示 feed。`window.WANDER_CONFIG.eventsEndpoint` 可替换列表地址，支持 `{coordinate_system?, events: EventView[]}`；真实数据提供图片与原站链接，省略/置 false `is_demo`。
- 高德代理为带合法 `callback` 的响应输出 JavaScript MIME，兼容浏览器 `nosniff` 策略；普通 JSON 仍输出 JSON。

地图坐标缓存对 SDK 输入使用独立副本：高德 `convertFrom` 会把传入数组成员原地转换为 `LngLat` 对象，不能再按原始数值数组读取。回归检查模拟了这一行为，覆盖景点初始化和路线转换。缩放控件采用 JS API 2 的 CSS 定位配置，控件错误不再导致整个地图回退。


## 附近活动、路线视野与天气（2026-11-13）

- 活动气泡显示标题、类别与费用；随拖动、缩放、定位重新布局，避让左右卡片和景点标签。景点继续使用原有 4A/5A 标签。远景减少气泡数量，放大后展示更多，不将所有文字挤在一个位置。
- 真实活动接口按当前 GCJ-02 视野 `bbox` 拉取，250ms 合并连续移动，取消旧请求并隔离迟到结果。静态演示 feed 不追加 API 参数，直接按视野筛选气泡。
- 进入方案或点击 A/B 后，仅使用当前方案计算视野范围，保留另一方案作为半透明对比。
- 空对话输入框位于卡片中间；发送后移到底部、消息区向上展开，保留历史入口。新聊天恢复初始布局，打开历史则保持聊天布局。
- 天气插件使用官方 `(err, data)` 约定，成功 `err = null`；地理编码/坐标转换继续使用各自的状态回调。支持 0℃，缺失或非法温度不会当成 0℃。
- 默认高德主题为官方浅绿 `amap://styles/fresh`（草色青），原地图回退仍使用现有浅绿样式；若需要精确复现旧底图颜色，可通过 `AMAP_STYLE` 配置已发布的自定义样式 ID。

参考：[高德天气回调](https://lbs.amap.com/api/javascript-api-v2/guide/services/weather)、[官方地图主题](https://lbs.amap.com/api/javascript-api-v2/guide/map/map-style)。
