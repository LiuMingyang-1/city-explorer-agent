# 下一阶段产品共识与三人分工规划

日期：2026-11-12。状态：团队讨论稿。
本文基于已落地的后端底座（会话持久化、上下文压缩、`user_memory` 自动蒸馏、`delegate_task` 同步子 Agent 编排及基础地图打点连线），梳理后续功能边界、交互闭环与三人（**Agent 同学**、**前端同学**、**爬虫同学**）的优先级拆解。

---

## 1. 核心产品与架构共识

### 1.1 产品生态位：地图做画布，AI 做唯一排期引擎

- **与纯聊天框（如豆包）的差异**：纯文字规划缺乏空间直觉，容易出现跨城折返，且局部微调往往重吐整篇长文。本产品以地图实时呈现动线、片区聚集度与通勤关系，支持结构化局部演进。
- **与传统地图规划工具（如圆周旅记）的差异**：不做“AI 只出初稿、后续退化为手动拖拽时间轴与勾选填空”的半传统模式。所有增删改、顺路重排与时间窗防冲突均由 AI 驱动并直接刷新地图状态；地图承担可视化与轻量点选输入（“点气泡喂给 AI”）。

### 1.2 前端组件策略：不做动态可变卡片，聚焦 3 个固定精品组件

- **不做开放式动态生成 UI（Generative UI）**：垂直城市探索场景无需让模型动态拼装任意 UI，避免样式失控与维护负担。
- **聚焦 3 个固定形态组件**，由后端结构化 JSON 驱动：
  1. **站点/活动详情卡**：完整渲染后端 `EventView` 已具备的封面图、票价区间、开放时间窗、场馆地址与原站链接。
  2. **多方案比选切换卡（Plan A / Plan B）**：承载并行探路产出的两套候选路线切换。
  3. **地图气泡预览卡**：点击地图活动点弹出摘要，支持一键带入对话。
- **开发节奏**：先完成“功能性交互闭环”，全局视觉美化（配色、间距、动效细节）集中在最后 1～2 天统一收口，避免字段调整导致样式返工。

### 1.3 多 Agent 与数据分工边界

- **交互形态**：坚持“主 Agent 唯一入口 + 子 Agent 封装为一次性 Tool（用完即关，运行轨迹落库、内存状态不常驻）”，不设跨轮常驻的“资讯 Bot / 酒店 Bot”，防止多 Bot 记忆串台与行程状态撕裂。
- **每晚静默采集 vs 实时联网探路**：
  - **主力底座（约 85% 场景）**：展览、演出、市集等活动排期不具备分钟级变化，由**每晚静默跑批入库**承担，保证本地 SQLite 毫秒级检索、坐标准确且零幻觉。
  - **子 Agent 真正发力的两类场景**：
    1. **多方向并行探路与空间比选**：开放需求下并行派发 2 个子任务深挖不同片区/主题，在地图上同屏对比。
    2. **长尾软性需求与实时避雷补盲（二期/P2）**：当本地库无匹配长尾去处（如“附近安静有插座的独立咖啡馆”）或用户追问排队/预约/临时闭馆细节时，由联网探路子 Agent 抓取网页并隔离脏上下文，只向主 Agent 回传干净结论。

## 2. Plan A / Plan B 双方案比选交互逻辑

1. **按需触发，不强凑双方案**：
   - 用户诉求明确（如“周六下午去曲江看展再逛书店”）→ 直接返回 **1 套方案**。
   - 用户诉求开放/模糊（如“周六下午有空，想找舒服的地方逛逛别太累”）→ 主 Agent 并行调用 `delegate_task` 探路，返回 **2 套风格或片区拉开差距的候选方案**（如 `方案 A：美术馆看展线` vs `方案 B：城墙根独立书店咖啡线`）。
2. **界面联动**：
   - 聊天区行程卡片顶部展示 `[ 方案 A | 方案 B ]` 切换滑块；
   - 切换滑块时，地图同步高亮对应路线（实线主色），另一条候选路线以半透明样式保留在图面做空间位置对比。
3. **模型感知与收敛闭环**：
   - Plan A 与 Plan B 均来自上一轮主 Agent 的结构化输出，完整保留在会话历史中，用户可直接口头指代（如“选 B，但把最后一站换个室内的”）。
   - 为消除模糊指代（如用户把滑块切到 B 后只输入“把第二站换掉”），前端发请求时附带当前激活方案标识（如 `active_plan: "B"`）。
   - 用户拍板并微调后，后续轮次收敛回单一生效行程。

## 3. Day 0 联调前置卡点（开工前三人当场拍板）

为避免前端等后端接口、Agent 等爬虫真实数据，正式铺开开发前先锁死以下两份契约，随后全员基于 Mock 数据并行推进：

1. **数据入库与坐标系契约（Agent 同学 ↔ 爬虫同学）**
   - 对齐 `src/data/schema.ts` 中 `events` 表全部字段口径：时间统一本地无时区 `"YYYY-MM-DDTHH:MM"`；`budget_min` / `budget_max` 单位为分（`0` 表示免费，`NULL` 表示未知）；`image_urls` 为合法 JSON 字符串数组。
   - **统一地图坐标系**：高德 API 返回 GCJ-02（火星坐标），当前前端 OpenFreeMap / OSM 底图使用 WGS-84。需当场约定入库存储坐标系及前后端转换位置，避免真实路线画在底图上偏移数百米（或评估底图与算路接口统一坐标系）。
2. **Web 聊天与地图协议契约（Agent 同学 ↔ 前端同学）**
   - 约定单方案与 Plan A/B 候选方案的响应 JSON 结构、站间真实道路轨迹 polyline 坐标与通勤耗时字段。
   - 约定请求体扩展字段：`active_plan`（当前滑块选中方案）、地图气泡点选带入的 `referenced_event_id`（或标准指代载荷）。
   - 约定流式状态事件（SSE）：透出“正在检索活动 / 正在并行探路方案 A 与方案 B / 正在校验路线时间”等阶段提示。
   - Agent 同学先行提供一份静态 Mock 响应样例，供前端同学独立完成组件开发。

## 4. 分优先级任务拆解（P0 / P1 / P2）

### P0：核心闭环（比赛演示生死线，必须优先打通）

> 阶段目标：跑通“真实西安活动数据 + 真实道路通勤计算 + 多 Agent 并行生成 AB 路线同屏比选”的完整主链路。

- **Agent 同学**
  1. 接入高德路径规划 / 距离计算工具，为 Agent 排期提供真实步行/公共交通耗时依据，并在响应中附带真实道路轨迹坐标与站间耗时。
  2. 升级输出契约与校验链路，支持 `单方案 / Plan A & B 双候选方案` 输出，并处理前端回传的 `active_plan` 上下文。
  3. 为对话接口补充流式阶段反馈（SSE），将 `delegate_task` 并行子任务的执行进度实时透传给前端。
- **前端同学**
  1. 升级行程站点卡片，完整展示活动封面图、票价区间、场馆名、推荐理由与原站链接。
  2. 实现 `[ 方案 A | 方案 B ]` 切换滑块，联动地图双路线高亮对比，并在继续对话时携带当前激活方案标识。
  3. 将地图上的两点直线虚线升级为真实道路轨迹线，并在路段或时间线上展示站间通勤时间。
  4. 接入聊天流式阶段状态展示，替换固定等待文案。
- **爬虫同学**
  1. 完成西安首批核心活动源（重点展馆展览、演出、市集等公开页面）采集与清洗，写入标准 `events` 表替换模拟种子数据。
  2. 接入高德地理编码校准场馆精确经纬度（严格执行 Day 0 约定的坐标系规则），落实过期活动过滤与重复记录合并。

---

### P1：高感知差异化亮点（P0 主线跑通后立即接入）

> 阶段目标：兑现“地图反向驱动 AI”与“可编辑个人长期记忆”两大亮点，拉开与普通聊天框和传统工具的体验差距。

- **Agent 同学**
  1. 提供近期有效活动列表只读接口（按时间窗与视口/城市筛选），供首页地图直接打点展示。
  2. 提供 `user_memory` 查询、手动编辑与清空接口。
  3. 支持对话请求携带地图点选的 `event_id` 上下文，让主 Agent 准确理解“把这个加进下午 / 帮我看看这个展合不合适”。
- **前端同学**
  1. 首页地图加载并渲染数据库内的近期真实活动气泡（与既有 4A/5A 地标分层或融合防遮挡）；点击气泡弹出预览卡，提供 `「加入行程 / 问问这个」` 快捷入口。
  2. 新增“我的偏好”轻量抽屉/浮层，展示 AI 自动蒸馏出的长期兴趣与出行节奏，支持用户直接修改或删除。
- **爬虫同学**
  1. 固化每晚定时静默增量抓取与更新脚本（含错误日志、来源 URL 与更新时间留存）。
  2. 提升 `thumbnail_url`（封面图）、`budget_min/max`（费用区间）与准确开放时段的字段覆盖率。

---

### P2：锦上添花与冲刺收口（视剩余时间取舍，绝不阻塞 P0/P1）

> 阶段目标：补齐长尾联网探路能力，完成全局视觉打磨与演示稳定性兜底。

- **Agent 同学**
  - 新增轻量联网补盲子 Agent 工具（如 `scout_web`）：仅当本地 SQLite 无匹配长尾需求，或用户询问排队、预约、避雷等实时主观信息时触发网页检索，清洗后回传结构化摘要与来源链接。
- **前端同学**
  - 集中 1～2 天进行全局 UI 视觉升级：统一卡片质感、色彩层级、地图高亮动效、空状态与异常重试体验。
- **爬虫同学 + 全员**
  - 人工核验一批西安当周高质量真实活动数据，准备 2～3 条端到端黄金演示路径（涵盖“模糊需求触发 AB 双路线比选 → 地图切换选定 → 点地图气泡追加站点 → 偏好记忆跨新对话生效”），确保比赛现场演示零翻车。
