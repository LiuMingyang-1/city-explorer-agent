# 产品规划

定位：以地图作为理解兴趣、规划出行的 Personal Agent 入口，而不是在普通
地图上加一个通用聊天框。计划参加
[传智杯 AI WEB 赛道](https://www.boxuegu.com/matchTrack/detail/?id=10037)。

**当前状态：** 已交付命令行 v0（实现见 [overview.md](../architecture/overview.md)、
[development.md](../development.md)）；本文件的地图前端、真实数据源、长期
偏好等均为规划目标，尚未实现。演示城市与数据管道由其他 worktree 的未合并
设计并行调研中，本文不代其做决定。

## 目标体验

- 首次打开时授权定位或手动选择位置；首页地图展示附近的景点、展馆，
  以及当前能获取到的近期展览、活动。
- 点开活动卡片看介绍、推荐理由和信息来源，可收藏或加入行程。
- 用户直接提出需求，例如：「这周六下午有半天时间，想看展、逛书店，不要太赶。」
- Agent 结合位置、日期、兴趣和交通时间，生成地图路线和可编辑的行程时间线，
  并附地点介绍、选择理由和注意事项。
- 用户可以说「这个不喜欢」「少走点路」，Agent 据此调整方案，而不是重新
  丢一篇长攻略；系统还可以另外生成更详细的行程说明。

## 想做出的亮点

- **界面精美。** 地图、活动卡片、行程时间线联动，推荐可探索、可修改。
- **Agent 真实调用工具。** 查询地点、检索活动、计算路线和时间再形成方案，
  不靠模型凭空编造地点和活动。
- **有可编辑的个人偏好。** 经用户确认后保存长期兴趣和出行节奏，并可查看、
  修改、删除；一次性的心情默认不写入长期记忆。
- 工具执行结果和用户反馈真正改变方案；不引入多 Agent 或复杂后台。

## 数据方案（候选，未验证）

- 地图、周边地点（POI）和路线候选高德；认证、有效 Key 以及接口连通仍待
  验证。工具既可经 MCP 也可经 HTTP 调用。
- 场馆位置不等于该场馆的近期活动；活动信息拟从少数公开文旅、展馆页面
  尝试采集，合规低频爬虫加人工核对，保留来源和更新时间。
- 不绕过登录或反爬限制，不采集私有接口。
- 最大风险是能否稳定获取真实的近期活动；不承诺全国、全量、实时覆盖。
- 质量底线：地址和日期必须核对，过期信息过滤，字段缺失明确提示；
  AI 不得补造活动、日期、价格或余票，预约和开放情况以原站为准。

## 明确不做

- 购票、支付
- 全国实时活动聚合
- 跨 App 自治执行
- 后台持续监控
- 复杂的多 Agent 或知识图谱基础设施

## 验收取向

- 活动可以追溯到来源、日期和地点；地图上的路线与行程安排一致。
- 按用户指定的目标日期过滤活动；修改偏好或约束后结果可解释且确实变化。
- 数据缺失或工具调用失败时明确提示，不让 AI 补造。
- 密钥不进入仓库，也不暴露在前端。

## 比赛材料（计划，未完成）
